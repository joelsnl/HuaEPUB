# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview
HuaEPUB (formerly novelDownloader) is a Python GUI application (PySide6 / Qt) for downloading Chinese web novels, optionally translating them to English (Google Translate, LibreTranslate, local Ollama, or optional Offline NMT via CTranslate2), optionally polishing machine English with local llama.cpp, and packaging them as EPUB files.

Modes: **Single**, **Multi** (block-paste URLs), **Library** (track novels, check/update for new chapters), and **Read** (in-app reader). **Server mode** serves the same app to browsers (`web/`): *This network* (HTTP, private/loopback clients, access code + QR) or *Anywhere* (HTTPS + password). While serving, the desktop tabs are swapped for a server screen; the browser is the app. Google Drive sync was removed; do not add it back. User data lives under `~/.huaepub/` (migrates from `~/.noveldownloader/` when present).

The release number lives only in the repo-root `VERSION` file. `core/updater.py` reads it. Do not copy it into the README, pyproject, Snap, or metainfo.

- `gui/` - PySide6 UI (`main_window`, pages, workers, dark `style.qss`). Window mixins live in `gui/window/` (`worker_host`, `reader_actions`, `library_actions`, `server_actions`, `look_actions`); every `@Slot` stays on `MainWindow` via MRO. Worker→UI must use `@Slot` methods on the main window (never bare lambdas — they can run on the worker thread and crash Qt). Menus: File (books / data / log / **Server mode…**), View (**Look**), Library (check / reset), Help (updates, How translation works, **Cache…**, About). No app keyboard shortcuts except **Y**/**N** on Yes/No dialogs. Window geometry is restored from settings. Library grid/list uses extended selection (**Select All** / **Select None** / **Invert**, or Ctrl/Shift-click); **Update**, **Remove**, and **Download EPUB** apply to the selection, while **Read** / **Open URL** / double-click use the current book. The **Read** tab prefers a local EPUB, else cached chapter HTML (on-demand site fetch for a missing chapter, then N+1 prefetch). With Translate on, cache HTML can be live-translated. Reading position is `reading.json` — local only.
- `gui/theme.py` + `gui/style.qss` - the Slips look. `style.qss` is a `string.Template` (`${ground}`, `${accent}`, …) rendered per palette; never hardcode colours in widgets (use object names such as `mutedLabel` / `hintLabel` / `eyebrow`). Six palettes match `web/static/app.css` exactly (a test checks). `ui_look`: `auto` (follows `styleHints().colorScheme()` live: dark → Catalogue at night, light → Catalogue) | `dark` | `light` | `indigo` | `gold` | `cinnabar` | `mist` | `random` (opt-in only). Hanken Grotesk + JetBrains Mono (OFL) are bundled in `gui/assets/fonts`; the CJK serif is not bundled (system fallback). `gui/widgets/slips.py` (`SlipStrip`, `SealMark` 译) replaces the progress bar.
- `gui/window/server_actions.py` - **SERVE** chip (tab-bar corner) and File → Server mode… (`gui/server_dialog.py`). Refuses to start while a desktop job or library check runs. While serving: central `QStackedWidget` shows `gui/widgets/server_screen.py`, Server mode / Library menu / Qwen glossary / Cache… are disabled, clipboard watch and startup resume/glossary offers are skipped. Stop: `options.apply_snapshot` from settings (the browser may have changed them) before anything persists, then library refresh + resume check. `closeEvent` stops the server (resume point kept) but leaves `server_enabled` on so the next launch serves again; a failed launch start turns it off and says so.
- `gui/dialogs.py` - QMessageBox helpers. Fusion underlines `&Yes`/`&No` but those are Alt+Y/N; bind **Y**/**N** only on Yes/No (and Yes / Not now) so the keys work. Do not bind other first letters (O, P, D, A, …). Use these instead of `QMessageBox.question/information/warning/critical`. Single / Multi completion uses `show_info_with_preview`. Cache / recent-download / rich HTML About boxes live here too.

- `core/tasks.py` - Qt-free job bodies shared by the desktop workers and server mode: `run_single`, `run_multi`, `run_library_update`, `run_library_update_all`. Every book goes through `download_one_novel` (fetch → build → record). Qt workers in `gui/workers/` are thin wrappers; do not fork the logic back into them.
- `core/branding.py` - product name, data-dir name, exe basename, and legacy aliases
- `core/parser.py` - `BaseParser`, `Chapter`/`NovelInfo` dataclasses (`Chapter.used_heuristic` when sites.json content selectors miss), parser registry, `CHROME_UA`, `create_http_session(*, ipv4=False, pool_size=None)` (curl_cffi Chrome impersonation with requests fallback), `fetch_info_and_chapters`
- `core/cleaner.py` - `ContentCleaner`: watermark/ad removal (Simplified + Traditional, ad divs with content), XHTML structure fixing, br-to-p conversion. Repeating site junk is learned from the first chapters via `core/ad_detect.py` when Clean is on — independent of Polish / llama.cpp.
- `core/ad_detect.py` - compare the first five chapter HTMLs; add recurring promo lines as extra cleaner literals. Do not start llama.cpp or download a GGUF for this.
- `core/translator.py` - Google (New translate-pa / HTML / Old gtx), Microsoft Edge, LibreTranslate, Ollama: concurrent translation with bounded multi-pass retry. Default Google is **New** (`translate-pa.googleapis.com/v1/translate`), same as Calibre Ebook Translator 2.4+ *Google (Free) - New*. Old gtx is still selectable. Unofficial engines use `GtxThrottle` (start 8, cool on 429, climb on success). LibreTranslate may pack. HTTP sessions are thread-local. `is_usable_translation` rejects empty/echoed Chinese. Cache writes are batched. Re-exports Ollama helpers from `ollama_setup.py` and throttle types from `gtx_throttle.py`.
- `core/gtx_throttle.py` - `RateLimitedError`, `GtxThrottle`, `parse_retry_after`, `jittered_backoff_seconds` (re-exported from `core.translator` for tests)
- `core/atomic_io.py` - `atomic_write_text` / `atomic_write_json(*, fsync=…)`. Settings and reading position fsync; library/glossary/resume jobs do not. Leave EPUB binary writes on `write_epub_atomic`.
- `core/translation/` - glossary protect/restore (`§G0§` placeholders), optional CTranslate2 opus-mt-zh-en adapter, and `NovelTranslator` (the pipeline facade). Built-in terms in `core/translation/data/novel_terms.json` (curated cultivation/wuxia pack, expanded in releases; not CEDICT and not grown by swallowing a general dictionary). Default glossary mode is **off** (names come straight from the translator; changing modes changes cache keys, so a book re-translates once). In **auto**, the pack is attached only when title/description/early chapter titles look like cultivation (strong markers such as 修仙 / 金丹 / 灵根 — not 公子 or 凡人 alone). Setting `translation_glossary`: `auto` | `xianxia` | `user` | `off`. User terms: `~/.huaepub/glossary.json` (local only); per-novel: `~/.huaepub/glossaries/<title>.json`. During the final translate pass, `harvest.py` mines names / sects / techniques from the book’s Chinese and romanizes them with **pypinyin** (not Google). Optional local Qwen (`qwen_glossary.py`, 7B+ polish GGUF already on disk) classifies those candidates with evidence — it does not invent terms from titles and does not write a global dump. Startup modal only if the GGUF is present; Help → Polish glossaries with Qwen shows Accept all / Discard. Does not rewrite shipped `novel_terms.json`. Legacy `glossary-qwen.json` is read only for cultivation books. Configure the glossary **before** prefetch (`prepare_translation` / `configure_glossary`) so cache keys include the pack fingerprint; harvest/Qwen may change the fingerprint for the final pass (prefetch warmup may miss — acceptable). Offline model cache: `~/.huaepub/nmt/` (HF https only, no invented SHA256). Hugging Face redirects may go to `*.cdn.hf.co` (allowed); do not allow all of `*.hf.co`. Prefetch does not download the ~320 MB model during chapter fetch — `ensure_nmt_model` runs on the translate pass, once per process failure. CUDA without cuBLAS falls back to CPU (not Google). Register CUDA 12 DLL dirs with `os.add_dll_directory` and **keep the returned cookie alive** (GC undoes the path); also `ctypes.CDLL` preload by absolute path. pip `nvidia-cublas-cu12` / toolkit / Ollama; do not treat CUDA 13 as sufficient. Do not add `huaepub/translator/` — keep this under `core/`. `ctranslate2` / `sentencepiece` are optional (`requirements-nmt.txt`); missing packages fall back to Google.
- `core/ollama_setup.py` - Ollama install/GPU/probe/pull (kept out of the translator retry/cache module).
- `core/local_polish.py` - after Google/LibreTranslate, KEEP/REPLACE polish via `core/polish/` (auto-installs llama.cpp + Qwen GGUF under `~/.huaepub/polish`; Ollama not required). In-memory on the same EPUB; logs via print() into `huaepub.log`.
- `core/polish/` - llama.cpp download/serve, hardware caps (3B/7B/14B), span KEEP/REPLACE. Tagger train (`train_tagger`) lives in `tagger_train.py`; runtime `get_tagger` / `SpanTagger` stay in `tagger.py`. Downloads go through `validate_polish_download_url` (GitHub + Hugging Face https only) and `safe_extract_zip` / `safe_extract_tar`. Verify SHA256 when GitHub publishes `digest` or `HF_GGUF_SHA256` has an official file hash. This cache stays on this PC. Do not make polish depend on Ollama.
- `core/epub_builder.py` - `EPUBBuilder` and `TranslatedEPUBBuilder` (ebooklib); `apply_translations` writes at the text-node level, never with raw string replacement. Atomic write (sibling `.tmp` then replace). Translated builds skip a second `clean_html`. `build_with_translation` delegates sequencing to `translate_then_build`.
- `core/download_runner.py` - UI-agnostic pause/cancel/chapter-cache/EPUB orchestration, including `translate_then_build` (clean → translate → polish → apply → write). Fetch ETA uses uncached/network samples; translate status names the engine (Google / Microsoft / LibreTranslate / Ollama / Offline NMT), segment counts, in-flight, current chapter, and ETA (packs for LibreTranslate, completed requests otherwise). Prefetch warms the translation cache and may fill `Chapter.translated_content` for preview (LibreTranslate, or Offline NMT only when the model is already on disk — Google does not hit gtx during fetch; NMT does not download ~320 MB during scrape). The final pass always extracts and runs `translate_texts_with_retry` (usable cache hits only — echoed Chinese is not treated as done). Completion notes cover leftover Chinese, heuristic chapters, and polish-cancelled. Cancel during translation raises `DownloadCancelled` (no EPUB). Cancel during polish still writes the EPUB (`polish_cancelled`). When translate is on, `prepare_translation` builds `NovelTranslator` before the sequential chapter loop so LibreTranslate prefetch can overlap `request_delay` without parallelizing scrapes. `library_epub_path` picks a book's EPUB path (its Library file name when tracked).
- `core/updater.py` - auto-updater against GitHub releases (`__version__` is read from the repo-root `VERSION` file — bump that file on each release). Frozen onefile relaunch must strip `_PYI_*` / stale `_MEI` env and set `PYINSTALLER_RESET_ENVIRONMENT=1`. Windows helper: **ShellExecute** a hidden `powershell.exe -File` (not a Popen child — the onefile bootloader kills those on exit). POSIX: `/bin/sh` or `/bin/bash` — **never** `sys.executable` when frozen. Relaunch the bare binary with double-fork + exec — **never** `/usr/bin/open` (that opens Terminal.app).

Bulk `get_translations_bulk` / `delete_translations`; cache keys collapse whitespace; chapter fingerprints store a translated node list. Default 2 GB cap; LRU by oldest stored chapter HTML first, then covers, TOCs, translations last; VACUUM after purge. Help → Cache… is the UI.

## Workflow
Source Input → Parse → Clean → Translate (optional; glossary protect → engine → restore; optional chapter prefetch during sequential fetch) → Polish English (optional, local llama.cpp) → Build EPUB.

Chapter downloads are sequential on purpose (per-site `request_delay` avoids bans); do NOT parallelize them.

Library updates rebuild a full EPUB from cache + new chapters. The library and EPUBs stay on this PC.

The **Read** tab prefers a local EPUB under the books folder, else cached TOC/HTML. A cache miss fetches one chapter (site `request_delay`, no translation/polish). Reading position is local `reading.json` only.

## Commands
- Run the app: `python3 app.py`
- Run tests: `python3 -m pytest tests/`
- Lint: `python3 -m ruff check .`
- Build executable: `python3 build.py`

## Conventions
- To support a new site: add an object to `parsers/sites.json` (domains + CSS selectors). Optional `chapter_list_next` / `content_next` for paginated TOCs / chapter bodies. Keep `generic` registered last. Do not add per-site Python modules or a WebToEpub extractor.
- Parsers must RAISE on failed content extraction (never return placeholder HTML); the app handles failures and retries them at the end of a run. If `sites.json` content selectors miss, GenericParser may still extract via density heuristic — log it and set `used_heuristic`.
- Text cleaning rules live in `core/cleaner.py`; output format changes in `core/epub_builder.py`. Do not run `clean_html` a second time on already-cleaned translated chapters.
- Default Google workers is 200 (capped at 200) as the **ceiling**. Unofficial gtx starts at 8 in flight, cools new requests on 429, climbs on success (floor 2). Do not restore “429 backs off that worker only; the other 199 keep going.” LibreTranslate may still pack. Polish does not use that worker count.
- Cancel during chapter fetch or Chinese→English translation: abort and write no EPUB (resume point is cleared). Cancel during polish: still write the EPUB with machine translation (`polish_cancelled`). Download EPUB stays disabled while a job is running.
- Cache is not timer-cleared. Default cap is 2 GB (`cache_max_mb`); oldest stored chapter HTML is evicted first. Translations are kept unless the file is still over the cap.
- Google Drive sync was removed. Do not add it back. `cache.db`, resume files, `reading.json`, `polish/`, `nmt/`, `server/`, `glossary.json`, `glossary-qwen.json`, and `glossaries/` stay on this PC.
- Polish binary/GGUF downloads must stay on GitHub / Hugging Face https hosts; extract via the safe zip/tar helpers; do not invent SHA256s for unofficial or split GGUFs.
- Auto-updates must fail closed without a matching `SHA256SUMS` entry; never fall back to unsigned `main.zip`. Release CI must publish `HuaEPUB-*.zip` (HuaEPUB binary only), `HuaEPUB-source.zip`, and `SHA256SUMS.txt`. Do not ship a NovelDownloader binary or `novelDownloader-source.zip` alias.
- Frozen updates (all OSes): GUI must quit after a successful download so the helper can swap/relaunch. Strip `_PYI_*` and set `PYINSTALLER_RESET_ENVIRONMENT=1` on every relaunch path. Frozen POSIX: launch `_update_helper.sh` via `/bin/sh` or `/bin/bash` — **never** `sys.executable` when frozen (that reopens the GUI). Prefer python3 inside the helper for replace; re-hash staged `_new_*` before `mv`. Relaunch with double-fork + exec — never `/usr/bin/open` on a bare binary. Windows: ShellExecute a hidden `powershell.exe -File` (not a Popen child of the onefile process).
- Accepting an app update hides the main window behind `UpdateProgressDialog` (`gui/dialogs.py`: app-modal, no close/Esc). The asset download streams (`_download_release_asset`, progress throttled to `DOWNLOAD_PROGRESS_INTERVAL`) so the bar shows real MB. On success the same dialog switches to `show_ready` with one **Restart now** button — never a second message box on top of it. A failed download restores the window. The startup update check runs at 5 s, after the GUI-thread startup jobs (Library cover refresh at 4 s, Qwen glossary GPU probe at 3.5 s): fired inside the Update prompt they froze its Yes button. Accepting an update restarts the app.
- Product fetches (pages, covers, LibreTranslate) must go through `safe_http_request` / `validate_fetch_url`, not raw `session.get` with automatic redirects.
- Product strings live in `core/branding.py` — prefer importing those over hardcoding.
- Settings writes are atomic (tmp+replace) under one lock for the full read-modify-write.
- Yes/No popups go through `gui/dialogs.py` so Y/N work without Alt. Do not bind other letter shortcuts. Do not use the static `QMessageBox.question` helpers.
- `closeEvent` during a download: persist the resume job, `request_cancel` (do not clear the resume point), wait up to 15s, `terminate` only as a last resort. Update-install close stays a short wait.
- Status copy should name the phase (Fetching chapters / Translating / Polishing / Writing EPUB). Completion dialogs with leftover Chinese, placeholders, heuristic chapters, or a cancelled polish pass use the title **Saved with warnings** — never a Success title with the warning only in the body.
- Server mode: never log the access code, password, cookies or open-link tokens. Remote mode is HTTPS-only (`ServerContext` refuses otherwise). Keep LAN mode's client-IP and Host checks. Browser jobs and desktop jobs must never run at the same time (the server screen replaces the tabs).
